# 客户端异步加载与定时同步验证

作者：jingyh。日期：2026-10-12。

本轮只调整加载、渲染与上报时机，保留页面模板、权限验证、播放统计以及原有歌曲身份和文件聚合规则。仓库其他未提交的界面与业务修改予以保留。

## 同步行为

- 普通歌单新增、修改、删除、歌曲增删和排序先在本地完成，默认每 30 秒提交最终状态。
- 喜欢独立计算成员差异，排序仍使用原排序接口。个人与公共歌单、喜欢分开记录。
- 播放器设置、音效、外观、收藏歌手与专辑、同步下载设置、缓存配置使用相同周期同步。
- 播放进度与队列分开保存和上报，避免每次进度变化序列化整个队列，也不覆盖歌单或最近播放。
- 与已确认状态相同不发送。喜欢后取消、设置修改后恢复、歌单新增后删除、队列恢复原状均零上报。
- IndexedDB 保存待提交快照和尝试发送状态；失败后保留，刷新可恢复，账号之间隔离。
- 如果旧修改已被发送且服务端可能已经生效，恢复旧值属于对服务端的实际纠正，会提交纠正状态。
- 手动保存、重新联网、页面隐藏或退出会尝试提交已有变化，空队列仍不请求。手动启动同步下载先提交该任务需要的配置。
- 新增服务器自定义缓存路径仍通过原接口验证权限和可写性。文件删除、下载、导入、管理员维护和不喜欢规则等实际服务器业务仍使用原接口。

## 加载行为

默认主界面先显示，本地缓存和网络恢复异步执行。搜索歌曲、播放队列和歌单详情按最多 20 行或约 6 毫秒分批提交 DOM，切换列表取消旧任务。歌曲播放先更新基础信息并解析播放流，歌词与队列渲染延后执行。

支持独立取得歌曲与详情的咪咕数字 ID 歌单使用一次 NDJSON 请求，先返回歌曲，再补充歌单信息；其他音源保持原 SDK 响应和歌曲完整性。未修改 SDK 的搜索、匹配、分页和播放业务逻辑。

## 验证

- 完整单元与真实系统回归：`node --test --test-concurrency=1 test/*.test.cjs`，349 项通过，零失败。
- 后续收尾变更另跑同步、设置、喜欢、下载与歌单操作定向回归，最终 47 项通过，零失败。
- HTTP/SQLite 系统测试覆盖本地编辑无请求、周期持久化、重启、账号隔离、跨设备喜欢不被歌单快照覆盖、播放状态独立存储，以及分阶段歌曲响应和旧 JSON 兼容。
- Playwright 浏览器验证 13 项通过：空周期零写入、缓存配置和喜欢撤销零上报、待同步喜欢刷新恢复、真实喜欢写入与取消、旧渲染取消及完整分批渲染。
- 500 首测试歌曲最终显示 500 行，首批 20 行，期间观察到 27 次事件循环处理。另验证 2000 首渲染任务可被新列表取消；该用例不代表 2000 首完整渲染耗时。
- 相关客户端脚本通过 Acorn 语法解析，`git diff --check` 通过。
- 测试使用独立临时 HTTP 服务与 SQLite 数据库。测试歌曲的封面 404 为虚拟 ID 导致；交互无未处理脚本异常。
- 未执行前后端生产编译、提交、推送或发布。

测试入口：`test/clientPerformance.test.cjs`、`test/clientPerformance.system.test.cjs`、`test/clientPerformance.browser.cjs`。前两者已加入 `test:unit` 和 `test:system`。
