## 1. 用户体验优先级和根因假设

用户最常做的是打开播放器、打开播放队列、选歌/切歌、滚动、看歌词、收藏/调整列表，然后把页面留在后台播放。按这个顺序优先优化，而非只减 JS 文件体积。

| 优先级 | 待证实的成本 | 负责任务 | 优先验证场景 |
|---|---|---|---|
| P0 | 全量列表 DOM、逐行封面候选/补全、全量聚合 | 02 | 5000 首队列首次打开、快速滚动、切歌只更新高亮 |
| P0 | 浏览器运行期 Tailwind 编译、大范围 DOM 观察、阻塞脚本 | 07a、07c | 冷启动、反复打开弹层、歌词页面切换 |
| P0 | 高频同步 localStorage、全歌单结构化克隆/序列化、重复落盘 | 07b | 歌单改一首、播放状态保存、账号切换 |
| P1 | timeupdate 重复查 DOM/写文本、读写布局交错、多个动画循环 | 07c | 连续播放、拖进度、歌词开/关、页面隐藏 |
| P1 | 封面/歌词冷请求、重复下载/解析、无容量的本地歌词缓存 | 05、08 | 第二次访问、页面刷新、网络弱/断开 |
| P1 | 事件/观察器未释放、无限增长缓存、过期异步响应 | 02、07c、08 | 连续使用 30 分钟、20 次视图往返、20 次切歌 |
| P2 | 大面积模糊、阴影/动画绘制成本 | 07c | 移动端滚动与歌词动画；有 trace 再调整 |

读码定位只能证明存在潜在成本，不能证明用户每次都走该路径。先追踪调用方与触发频率，记录“热路径/低频路径/未调用旧代码”。旧分支已修好的项目只验证，不反复重新实现。

## 3. 测量工具与隔离数据

### 3.1 perf_probe.js

新增 client/music/js/perf_probe.js，只有显式 ?perf=1 时开启。不开启时不注册 observer、不收集计数、不创建周期任务，公共方法为空操作；不能默认打印日志影响测量。

启用后提供：
- PerformanceObserver longtask（能力检测；不支持写 N/A，不填 0），统计 >50ms、>100ms 数量、最大值和总时长；缓冲有上限，不能无限累积。
- performance.mark/measure 命名：boot:shell、boot:interactive、lists:open、queue:open、queue:highlight、library:page、storage:write、lyric:ready、media:cache-hit。标记放在具体业务边界，不把所有 Promise 完成都当成可交互。
- 调试计数：有效列表行节点、封面网络并发/命中、localStorage 读写次数/字节、IDB 写歌单数/估算字节、renderMyLists 调用/真正更新次数、observer 回调、活跃 rAF/监听器。在各任务实现内部埋点，不全局猴子补丁生产 API。
- 请求与资源从 Resource Timing/DevTools 获取；跨域 timing 缺字段需标注，不当作零耗时。
- snapshot() 导出汇总 JSON；不包括歌曲正文、token、个人路径。调试计数按视图分桶，关闭后清理 observer 与 mark。
- 不能每帧 console.log；不能为了统计大小在热路径 JSON.stringify 全歌单。

### 3.2 数据生成器

新增 scripts/perf/generate-dataset.cjs，固定随机种子，默认只写 --out 指定的临时目录；命令没给隔离输出目录应拒绝写入。若需要导入浏览器/后端，只允许专用测试账号，显式确认目标账号，无生产自动导入逻辑。

三组数据：
- S：200 首队列/歌单、2000 首库、100 条最近播放。
- M（统一验收）：1 个 5000 首歌单/队列、2 万首库、1000 条最近播放，包含多个歌单、同曲多来源、多版本文件。
- L（压力）：1 万首队列、5 万首库，仅用于找退化曲线，不强求与 M 相同时间预算。

封面分组：无封面、已有后端封面、已有客户端封面、远程成功、远程失败；歌词：普通/翻译/罗马音/逐字、无歌词、超长歌词。可复用少量合法音频样本用于实际播放；占位元数据不宣称测试了音频解码或真实 tag 提取。2000 目录扫描数据由 04 扩展，避免混用“只有 JSON”与“实际文件树”的结果。

### 3.3 测量环境记录

每份报告必须写：commit、浏览器版本、OS、CPU/内存、窗口尺寸/DPR、服务器设备/文件系统、网络延迟/带宽、数据种子与条数、功能开关、SW 状态、缓存层状态。真实低配设备与 Chrome 4x CPU 降速分别记录，4x 只是模拟，不代表所有用户设备。

冷/热分开：
- 静态冷：使用隔离浏览器配置，清理 HTTP/SW 静态缓存；账户数据保留/迁移情况单列。
- 媒体冷：仅清空 08 当前账号媒体缓存；不要删歌单和未同步队列。
- 热：同一数据二次打开、缓存已存在。
- DevTools “Disable cache” 只影响其中一些缓存层；不得把它当作所有缓存都清空。
- 启动采至少 10 次用于中位数；要给 P95，至少 30 次，标注样本数和计算法。不够则写“样本不足”，不编造 P95。
- 长任务/fps 用 Performance trace 与 frame 数据交叉核对；简单 rAF 间隔只能当辅助指标，不声称精准 GPU 帧率。

## 4. 用户场景矩阵与执行步骤

| 场景 | 具体操作 | 要观察的成本/正确性 |
|---|---|---|
| 首次进入 | 登录测试账号，冷启动到可点击播放/导航 | 网络瀑布、script 执行、样式编译、认证配置顺序 |
| 打开播放队列 | M 数据，播放中打开抽屉，再关开 5 次 | 首行出现、可交互、DOM 上限、封面请求范围、聚合次数 |
| 大歌单滚动 | 持续滚动 10 秒，快速拉到底后停住 | 帧、长任务、离屏队列、停留处优先、行复用后的封面 |
| 切歌 | 连续切 20 首、上一首/下一首、手动选歌 | 不全量重绘、正确高亮、旧歌词/封面不覆盖当前歌 |
| 音乐库翻页 | 1→2→1 页，搜索输入，排序切换 | 每次只取当前页、取消旧请求、热页复用、版本失效 |
| 歌单编辑 | 插入中间、移除、重排、收藏、改名 | 数据无损、revision 正确、只写变化歌单、同步顺序 |
| 持续播放 | 前台 60 秒、歌词关闭/开启各一次 | timeupdate、rAF、style/layout/paint、进度与歌词一致 |
| 后台播放 | 隐藏 2 分钟再恢复，音频继续 | 无装饰循环/反复 DOM 写，锁屏/MediaSession/恢复位置 |
| 本地媒体复用 | 缓存后刷新、临时断网、同曲再播 | 封面歌词本地命中、不请求源站、完整歌词字段 |
| 本地随机/漫游 | 完整5000首缓存仅挂60行、断开后端、增删未上报后抽样 | 候选不限当前页、选择不fetch、权重增量即时、预读/next一致 |
| 账号切换 | A→B→A，夹带慢网络响应 | scope 隔离、取消/过期防护、未同步数据不丢 |
| 生命周期 | 同一页面/弹层往返 20 次，运行 30 分钟 | observer/listener/rAF 有界、无 detached DOM 增长 |
| 异常存储 | 配额/隐私模式/IDB blocked/损坏模拟 | 播放可用、持久化失败有状态、关键用户数据不静默丢失 |

DevTools 记录流程：先无 profiler 的时间样本，再单独录制带 Screenshots/Memory 的 trace；启动用 reload trace，交互录制至少覆盖操作前后各 1 秒。查看 Main 上 top-down/bottom-up、DOM 节点、Recalculate Style/Layout、长任务调用栈、Network。给出最高成本的 3～5 个函数及前后占比，不只截图一个总分。测内存做基线、往返、空闲回收后的对比，不把强制 GC 当作正式用户体验。

## 5. 统一预算与通过口径

| 指标（M 数据） | 初始目标 | 口径与限制 |
|---|---|---|
| 打开已有本地队列/歌单首屏可交互 | P50 ≤300ms、P95 ≤500ms | 从用户打开到首屏行和交互可用；远程/迁移启动单列 |
| 虚拟列表挂载行数 | 典型桌面 ≤60；高视口按可见行+overscan解释 | 不要求 4K 窗口永远 <60；分页模式单视图 <200 行 |
| 切歌高亮更新 | P95 单次脚本 ≤16ms | 不包含网络、解码、歌词获取；不能重聚合整个队列 |
| 滚动 | 目标 ≥50fps、交互不出现 >100ms 长任务 | 固定设备/视口/4x CPU；分析持续 >50ms 任务，不能只盯100ms |
| 封面网络请求 | 全局同时 ≤6 | 包含列表、播放器、重验证；纯本地 IDB 命中不计网络 |
| 播放热路径 | 脚本平均 ≤5ms/秒，P95 一秒窗口 ≤10ms | 歌词关闭；打开逐字歌词/可视化另报成本与帧质量 |
| 隐藏页面/空闲 | 目标业务主线程 <200ms/分钟 | 音频解码、浏览器内部不混入；允许协议心跳/必要可靠存储，禁新增 UI 1秒轮询 |
| 存储写放大 | 改一首仅写相关歌单；未改歌单写0次 | 如同步仍需完整协议快照，单列序列化成本，不能冒称全链路增量 |
| 媒体热命中 | 未过期/版本匹配时源站请求0次 | 有版本变化、主动刷新、到期重验证另计；普通 HTTP 支持也验证 |
| 本地随机/漫游 | 已准备choose P95≤5ms；准备P50≤100ms/P95≤300ms | 首次IDB读取单列，点击/next不请求候选/权重；后台同步另计，按09正确性验收 |
| 启动资源成本 | 先报基线，目标减少无效同步执行 | 不提前承诺固定百分比；对 CSS/JS 压缩前后字节分别记录 |

达标且功能回归通过才记“通过”。未达标写原因、最大热点、已做尝试和下一步；正确性不能为了预算牺牲。首屏统计不能停在占位符，而后续主线程仍冻结；还要观察首屏后 5 秒。

## 6. 共同实现规则

1. 少做工作优先于把全部工作搬到异步：先限制数据/DOM/请求范围，再缓存，再让出任务。Worker 不解决重复全量读取，Promise.resolve/microtask 也不保证浏览器绘制。
2. 先读后写：一帧批量测量，再统一 DOM 写。可见渲染用 rAF 合并；后台可靠存储不能依赖 rAF。
3. 所有异步结果带 scope + generation/requestId，进入缓存/写 DOM 前再验证；复用节点时不能只验证它还在 document。
4. 缓存必须有身份、版本、失效和容量；不能以对象引用、首尾 ID 推断中间内容未变。
5. 可取消作业须清理监听器、observer、rAF、timer、对象 URL；功能销毁后不得再写 DOM。
6. observer/事件调度器优先局部复用，不建立过度通用“事件总线+调度框架”。有两处真实重复需求才提炼。
7. 不改变播放次序、拖拽、多选、淡入淡出、锁屏、音效、歌词对齐、主题与辅助操作；减少 motion 可作为用户偏好，不能擅改视觉。
8. Worker、scheduler、idle、StorageManager 全部能力检测；普通 HTTP、移动 Safari、独立静态网关的差异需报告。
9. 只加必要构建依赖；新异步模块不要引入前端运行时框架。
10. 分阶段可回退：先观察/量化，低风险热路径，然后存储迁移。回退前先安全处理新格式与未同步修改，不能切开关就读陈旧数据。
