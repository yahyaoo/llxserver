## 交付结构与兼容边界

源码固定为 `server/` 与 `client/`，部署入口集中在 `deploy/`。整体、独立服务端、独立客户端均提供 Node ZIP、Docker、桌面与 fnOS 入口。独立客户端只带网页、连接配置及流式网关；服务端只带业务、SQL 和公开静态目录元数据，两端通过 HTTP / WebSocket 连接。

根引导配置使用 `server.xxx`、`client.xxx`，独立包分别拥有 config.js，环境变量优先。业务配置与状态继续使用管理、音乐两个 SQLite 库。旧配置显式导入、数据库迁移、权限与下载行为保持现有规则。

图标、封面、登录页、托盘和 fnOS 图标统一为新品牌；默认主题为樱花粉。客户端图标滤镜随用户选择的主题变化，已保存的主题优先。法律版权、上游出处、已有整体安装 appId 与 fnOS 应用身份保留。

## 分页脚本加载回归验证

`batch_pagination.js` 先于 `app.js` 加载，却在末尾导出了由 `app.js` 定义的 `goToPage`，导致启动抛出 `ReferenceError`。删除这条错误导出，保持 `app.js` 的全局搜索跳页实现及已有列表分页逻辑。

新增五项回归测试，验证先加载批量脚本不抛异常、应用跳页入口不被覆盖、本地上下页及首末页、跳页边界，以及网络续页失败后按钮恢复。完整单元测试 91 / 91 通过。

真实浏览器加载临时实例，确认控制台不再出现 `goToPage` 未定义错误，`goToPage`、`nextPage`、`prevPage`、`jumpToPage` 和 `changeItemsPerPage` 均为可调用函数。完整系统测试继续验证整体与两端独立 ZIP 启动、接口及 SQLite 数据持久化。
